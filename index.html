What is MIGA E&S Portal 2.0?

The MIGA E&S Portal 2.0 is an enterprise web application for the Multilateral Investment Guarantee Agency (MIGA), a member of the World Bank Group. It manages the complete lifecycle of MIGA-guaranteed investment projects — from initial pipeline evaluation through active portfolio monitoring, reporting, and eventual closure.

The portal digitalizes Environmental & Social (E&S) due diligence against IFC Performance Standards PS1–PS8, tracks Environmental & Social Action Plans (ESAPs), monitors Annual Monitoring Reports (AMRs), and provides real-time analytics dashboards for 243+ active portfolio projects and 130+ pipeline projects.

243 Portfolio Projects

Active MIGA-guaranteed investments under ongoing E&S monitoring across 60+ countries.

130 Pipeline Projects

Projects under E&S due diligence — 75 active, 51 slow-moving, 4 leads.

40+ REST Endpoints

Full REST API across 6 groups: Projects, Monitoring, ESAP, DueDiligence, Dashboard, EsInsights.

IFC PS1–PS8

Full compliance assessment against all 8 IFC Performance Standards with automated ESRR scoring.

Getting Started › Quick Start Guide

Quick Start Guide

Get up and running with MIGA E&S Portal 2.0 in minutes. Follow these steps to log in, navigate, and complete your first workflow.

Step-by-step: First Login to First Task

1

Access the Portal

Navigate to migaportalclouddev.worldbank.org/espipeline in your browser (Chrome or Edge recommended). Use your World Bank credentials to log in via SSO.

2

Review the E&S Dashboard

The dashboard loads automatically after login. Review your Unassigned Projects count, AMR Outstanding count, and the MSV summary for your portfolio. Use the "Filter By" dropdown to scope to your own projects.

3

Navigate to Your Projects

Click Projects in Pipeline → My Projects to see your assigned pipeline projects. Or Projects in Portfolio → My Projects for active guaranteed projects. Use the Search bar to find a specific project by name or ID.

4

Open a Project & Complete Due Diligence (Pipeline)

Click any Project ID to open the detail view. Navigate to the Due Diligence tab. Set PS1–PS8 applicability (Yes/No). Score Management Factors, Performance Factors, and Communication Factors (1–3). Click Assess ESRR to generate the risk rating.

5

Create ESAP Actions (if required)

Navigate to the ESAP tab. Toggle "Is ESAP Required?" to Yes. Click Add to create action items with due dates and deliverables. Save the ESAP for review.

6

Add a Monitoring Activity (Portfolio)

For portfolio projects, go to the Monitoring tab. Click Add New Monitoring Activity. Set the Fiscal Year, check AMR Review, enter the Reporting Period dates, and save. The dashboard AMR counters update automatically.

7

Generate a Report

Click Reports in the top navigation. Select a report type (e.g., AMR Submission Report or ESAP Status Report). Apply filters and click Export to download as Excel.

CQRS + MediatR Pattern

The portal uses Command Query Responsibility Segregation (CQRS) implemented via the MediatR library. This means:

Queries (reads like GetPortfolioProjects) use dedicated Query Handlers that only fetch and aggregate data — no side effects
Commands (writes like SaveMonitoringActivity) use Command Handlers that validate business rules before persisting
Controllers are thin routing layers — they dispatch to MediatR and return the result, containing zero business logic
Handlers are independently unit-testable and replaceable without changing the controller

Portfolio Projects — Full Sequence Flow

When a user clicks "Portfolio Projects" in the UI, this exact sequence runs:

MediatR Query Handler Pattern

This is the canonical pattern used throughout the codebase. Every "get" operation follows this exact shape:

C# — PortfolioProjectsQueryHandler.cs
// Query definition — immutable request object
public record PortfolioProjectsQuery(
    PortfolioProjectsRequest Request
) : IRequest<PortfolioProjectsResponse>;

// Handler — registered automatically by MediatR DI
public class PortfolioProjectsQueryHandler
    : IRequestHandler<PortfolioProjectsQuery, PortfolioProjectsResponse>
{
    private readonly IPortfolioProjectsService _service;

    public PortfolioProjectsQueryHandler(
        IPortfolioProjectsService service)
    {
        _service = service;
    }

    public async Task<PortfolioProjectsResponse> Handle(
        PortfolioProjectsQuery query,
        CancellationToken cancellationToken)
    {
        // All business logic lives in the service layer
        var projects = await _service.GetPortfolioProjectsAsync(
            query.Request, cancellationToken);

        return new PortfolioProjectsResponse
        {
            Projects = projects,
            TotalCount = projects.Count()
        };
    }
}

Service Layer Pattern

C# — PortfolioProjectsService.cs
public class PortfolioProjectsService : IPortfolioProjectsService
{
    private readonly IProjectsRepository    _projectsRepo;
    private readonly IIntegrationService   _integrationSvc;
    private readonly ICommonService         _commonSvc;

    public async Task<IEnumerable<PortfolioProjectInfo>>
        GetPortfolioProjectsAsync(
            PortfolioProjectsRequest request,
            CancellationToken ct)
    {
        // 1. Fetch core data from DB
        var projections = await _projectsRepo
            .GetPortfolioProjectionsAsync(request, ct);

        // 2. Enrich with project details
        var details = await _projectsRepo
            .GetProjectApplicationDetailsAsync(request, ct);

        // 3. Fetch ES scores from Integration Service
        var esScores = await _integrationSvc
            .GetEsScoreAndPhaseLookups(ct);

        // 4. Merge all data sources
        return MergeProjectData(projections, details, esScores);
    }

    private IEnumerable<PortfolioProjectInfo> MergeProjectData(
        IEnumerable<ProjectionData> projections,
        IEnumerable<ProjectDetail> details,
        EsScoreLookup esScores)
    {
        return projections.Join(details,
            p => p.EsId, d => d.EsId,
            (p, d) => new PortfolioProjectInfo
            {
                EsId        = p.EsId,
                ProjectName = d.ProjectName,
                EsrrScore   = p.EsrrScore,
                AmrDueDate  = p.AmrDueDate,
                EsPhase     = esScores.GetPhase(p.EsId)
            });
    }
}

Repository Pattern

C# — ProjectsRepository.cs (Dapper)
public class ProjectsRepository : IProjectsRepository
{
    private readonly IDbConnection _db;

    public async Task<IEnumerable<ProjectionData>>
        GetPortfolioProjectionsAsync(
            PortfolioProjectsRequest request,
            CancellationToken ct)
    {
        var sql = @"
            SELECT
                p.EsId,
                p.ProjectStageId,
                p.AmrDueDate,
                r.EsrrRating,
                r.EsrrScore,
                h.HighRiskFlag
            FROM   dbo.ESProjects p
            LEFT JOIN dbo.ESRRRatings  r ON r.EsId = p.EsId
            LEFT JOIN dbo.HighRisk     h ON h.EsId = p.EsId
            WHERE  p.IsPortfolioProject = 1
              AND  (@FiscalYear  IS NULL OR p.FiscalYear = @FiscalYear)
              AND  (@RegionKey   IS NULL OR p.RegionKey  = @RegionKey)";

        return await _db.QueryAsync<ProjectionData>(
            sql,
            new { request.FiscalYear, request.RegionKey });
    }
}

API Controller (Thin Layer)

C# — ProjectsController.cs
[ApiController]
[Route("api/esrd/[controller]")]
[Authorize]
public class ProjectsController : ControllerBase
{
    private readonly IMediator _mediator;

    public ProjectsController(IMediator mediator) =>
        _mediator = mediator;

    [HttpPost("GetPortfolioProjects")]
    public async Task<IActionResult> GetPortfolioProjects(
        [FromBody] PortfolioProjectsRequest request)
    {
        // Controller does NOTHING except dispatch to MediatR
        var result = await _mediator.Send(
            new PortfolioProjectsQuery(request));

        return Ok(result);
    }

    [HttpPost("SaveGbvQuestionnaires")]
    public async Task<IActionResult> SaveGbvQuestionnaires(
        [FromBody] SaveGbvQuestionnairesCommand command)
    {
        var result = await _mediator.Send(command);
        return Ok(result);
    }
}

React Component — API Call Pattern

JavaScript — usePortfolioProjects.js
import { useState, useEffect } from 'react';
import api from '../services/api';

export function usePortfolioProjects(filters) {
    const [projects, setProjects] = useState([]);
    const [loading, setLoading]  = useState(false);
    const [error, setError]      = useState(null);

    useEffect(() => {
        const fetchProjects = async () => {
            setLoading(true);
            try {
                const { data } = await api.post(
                    '/Projects/GetPortfolioProjects',
                    {
                        FiscalYear:          filters.fiscalYear,
                        RegionKey:           filters.region,
                        ManagementGroupCode: filters.mgmtGroup,
                        EsSpecialist:        filters.specialist
                    }
                );
                setProjects(data.Result ?? []);
            } catch (err) {
                setError(err.message);
            } finally {
                setLoading(false);
            }
        };
        fetchProjects();
    }, [filters]);

    return { projects, loading, error };
}

Pattern note: All API responses use the standard envelope: STATUS, STATUS_CODE, NOTIFICATIONS[], Result. Always destructure data.Result for the actual payload.

Key Relationships

SQL
-- One project can have many monitoring records (one per fiscal year)
ALTER TABLE ESMonitoring
    ADD CONSTRAINT FK_Monitoring_Project
    FOREIGN KEY (EsId) REFERENCES ESProjects(EsId);

-- One project has many ESAP actions
ALTER TABLE ESEsapActions
    ADD CONSTRAINT FK_Esap_Project
    FOREIGN KEY (EsId) REFERENCES ESProjects(EsId);

-- One project has one DueDiligence record per stage
CREATE UNIQUE INDEX UX_DueDiligence_EsId_Stage
    ON ESDueDiligence (EsId, ProjectStageId);

-- Typical query — get portfolio projects with latest ESRR
SELECT
    p.EsId, p.FiscalYear,
    c.ContractNumber, c.ExpiryDate,
    r.EsrrRating, r.EsrrScore,
    m.AmrDueDate, m.AmrReceivedDate
FROM      ESProjects        p
JOIN      ESContracts       c ON c.EsId = p.EsId
LEFT JOIN ESRRRatings       r ON r.EsId = p.EsId AND r.RatingType = 'M'
LEFT JOIN ESMonitoring      m ON m.EsId = p.EsId
WHERE p.IsPortfolioProject = 1
ORDER BY p.EsId;

Glossary

Key terms, acronyms, and definitions used throughout the MIGA E&S Portal 2.0 and this documentation.

TermDefinition
AMRAnnual Monitoring Report — submitted by the guarantee holder annually detailing the project's E&S performance against the agreed ESAP
CAOCompliance Advisor Ombudsman — independent IFC/MIGA oversight function that handles E&S performance complaints from affected communities
CQRSCommand Query Responsibility Segregation — software architecture pattern separating read operations (queries) from write operations (commands)
E&SEnvironmental and Social — refers to the environmental and social impacts, risks, and management practices of an investment project
ESAPEnvironmental and Social Action Plan — contractual list of actions a guarantee holder must complete as a condition of the MIGA guarantee
ESDDEnvironmental and Social Due Diligence — the full assessment process conducted by E&S Specialists for pipeline projects
ESMSEnvironmental and Social Management System — systematic framework for managing E&S risks at the project/enterprise level
ESRREnvironmental and Social Risk Rating — the risk rating assigned to a project. (D) = Due Diligence stage; (M) = Monitoring stage
GBVGender-Based Violence — specific risk category assessed for all MIGA projects via a dedicated questionnaire
IFCInternational Finance Corporation — sister organization to MIGA within the World Bank Group
MediatROpen-source .NET library implementing the Mediator pattern, used for CQRS message dispatch in this system
MIGAMultilateral Investment Guarantee Agency — World Bank Group member providing political risk insurance to promote FDI in developing countries
MSVMonitoring Site Visit — a physical or virtual visit to a project site for E&S compliance verification
PS1–PS8IFC Performance Standards 1–8 — internationally recognized E&S risk management standards applied to all MIGA-guaranteed projects
PRIPolitical Risk Insurance — the core guarantee product MIGA offers to investors and lenders
SEA/SHSexual Exploitation and Abuse / Sexual Harassment — a GBV risk sub-category tracked under MIGA's gender framework
SIPStrategic Initiative Project — a high-priority pipeline project categorization requiring expedited review
WBGWorld Bank Group — umbrella comprising IBRD, IDA, IFC, MIGA, and ICSID

System Overview

MIGA E&S Portal 2.0 — what it does, who uses it, and how the modules connect.

The MIGA E&S Portal 2.0 is an enterprise web application for the Multilateral Investment Guarantee Agency (MIGA), a World Bank Group member. It manages the full E&S lifecycle of guaranteed investment projects across 60+ developing countries.

Module Map

📊 Dashboard

Central analytics: ESRR distributions, AMR tracking, MSV status, pipeline vs portfolio metrics. Real-time, filterable by specialist or all members.

🚀 Projects in Pipeline

130+ projects under ESDD evaluation. Full due diligence workflow: PS1–PS8 scoring, ESRR generation, ESAP creation, GBV assessment, document upload.

📁 Projects in Portfolio

243+ active guaranteed projects. Ongoing monitoring: AMR reviews, site visits, virtual monitoring, ESAP follow-up, High Risk tracking.

🗃️ Shelved Projects

181 terminated projects — DECLINED, WITHDRAWN, NOT GOING FORWARD, DESELECTED. Retained for audit and compliance.

📈 Reports

12 pre-built reports: High Risk, ESAP Status, AMR Submission, ESRR Scores, Monitoring Trends, Major Incidents, Nature Finance.

⚙️ Other Initiatives

9+ active WBG/IFC cross-collaboration initiatives and CAO Policy action items tracked with deadlines and status.
